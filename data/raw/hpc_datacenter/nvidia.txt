										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p>Kubernetes, the open source system that manages how applications run across thousands of AI factories, has become the foundation for AI, and the demands on it are only growing.</p>
<p>To help meet them, NVIDIA is deepening its commitment to open source at <a target="_blank" href="https://www.nvidia.com/en-us/events/kubecon-and-cloudnative-con-north-america/">KubeCon + CloudNativeCon</a>, the flagship conference for the Kubernetes and cloud-native communities.</p>
<p>NVIDIA is contributing <a target="_blank" href="https://github.com/ai-openshell">NVIDIA OpenShell</a>, an open source runtime for securing and governing autonomous agents, to the Cloud Native Computing Foundation (CNCF), a nonprofit that is part of the Linux Foundation and the host of KubeCon. As a CNCF Sandbox project, OpenShell will be governed by the organizations building it into their products and strengthened by the expertise of security professionals worldwide.</p>
<p>NVIDIA is also contributing to <a target="_blank" href="https://developer.nvidia.com/blog/agent-substrate-advancing-kubernetes-for-agents-at-scale/">Agent Substrate</a>, an open source Google-led framework for operating long-running agent workloads at scale on Kubernetes that has been accepted into the CNCF Sandbox.</p>
<p>Additionally, NVIDIA announced new components of the <a target="_blank" href="https://www.nvidia.com/en-us/data-center/products/dsx/">NVIDIA DSX AI Factory Platform</a>: <a target="_blank" href="https://developer.nvidia.com/blog/manage-kubernetes-clusters-for-gpu-infrastructure-with-nvidia-kubernetes-engine">NVIDIA Kubernetes Engine</a>, NVIDIA Kubernetes Recipes and <a target="_blank" href="https://developer.nvidia.com/blog/start-and-restore-gpu-workloads-in-seconds-with-nvidia-snapshot"><span style="font-weight: 400;">NVIDIA Snapshot</span></a>. These tools help teams deploy, manage and scale GPU infrastructure on Kubernetes for AI factories.</p>
<p>Together, these advancements mark a step forward in making Kubernetes the leading foundation for AI workloads at scale — empowering developers to build safer, more efficient AI infrastructure for the future.</p>
<h2><strong>Securing AI Agents in the Open</strong></h2>
<p><span style="font-weight: 400;">NVIDIA’s contribution of OpenShell to CNCF puts security infrastructure for autonomous agents in the community’s hands to build, inspect and improve — accelerating development and hardening its safeguards. </span></p>
<p><span style="font-weight: 400;">“The cloud-native community has a new infrastructure challenge: giving agents secure environments in which to operate,” said Jim Zemlin, CEO of the Linux Foundation. “NVIDIA’s contribution of OpenShell to CNCF gives developers a shared foundation to build on and an opportunity to shape how agent security evolves. Bringing this work into the community enables broader collaboration on infrastructure that will be critical to the next generation of cloud-native applications.”</span></p>
<p><span style="font-weight: 400;">OpenShell gives organizations control over what AI agents can do. It applies deterministic controls to agent activity, so teams can enforce policies as agents use tools, access inference services and execute workloads. Its extensible architecture lets teams connect their own compute, inference providers, credential storage and monitoring tools. This allows organizations to apply governance across different deployment environments while integrating OpenShell with their existing enterprise systems.</span></p>
<p><span style="font-weight: 400;">Hundreds of organizations have put OpenShell to use, and the project has received tens of thousands of contributions in less than a year since launch. </span></p>
<h2><strong>Scaling Agent Execution on Kubernetes</strong></h2>
<p><span style="font-weight: 400;">Governing agents is only part of the challenge. Organizations also need to deploy them at scale.</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;">NVIDIA is contributing to Agent Substrate, a </span><span style="font-weight: 400;">Google</span><span style="font-weight: 400;">-originated project in the CNCF Sandbox, and ensuring it works with </span><a target="_blank" href="https://developer.nvidia.com/dynamo"><span style="font-weight: 400;">NVIDIA Dynamo</span></a><span style="font-weight: 400;"> for model inference and </span><a target="_blank" href="https://kai-scheduler.dev/"><span style="font-weight: 400;">KAI Scheduler</span></a><span style="font-weight: 400;"> for shared cluster resource allocation. This effort brings together agent execution, inference serving and resource scheduling on Kubernetes.</span></p>
<p><span style="font-weight: 400;">Agent Substrate preserves agent environments between tasks while releasing compute when agents are idle. By suspending and resuming those environments across a shared pool of agents, it lets teams scale agent workloads without keeping dedicated compute running for every session. </span></p>
<p><span style="font-weight: 400;">NVIDIA and </span><span style="font-weight: 400;">Google</span><span style="font-weight: 400;"> are also collaborating on an integration of OpenShell and Agent Substrate, so enterprises can secure and govern agents across clouds and on-premises systems.</span></p>
<h2><strong>Building an Open Foundation for AI Factories</strong></h2>
<p><span style="font-weight: 400;">AI factories need to offer customers managed Kubernetes services while retaining control of their infrastructure, software and customer experience. Three new open source projects extend the DSX AI Factory Platform to make Kubernetes easier to run and inference faster to scale.</span></p>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">Simulation, which has long been the proving ground for robots learning to walk, roll and hop, is now helping researchers teach robots tasks that require a finer touch: aligning gears, connecting cables and assembling small components. </span></p>
<p><span style="font-weight: 400;">The shift from locomotion to manipulation is taking center stage at this week’s </span><a target="_blank" href="https://www.nvidia.com/en-us/events/corl/"><span style="font-weight: 400;">Conference on Robot Learning (CoRL)</span></a><span style="font-weight: 400;"> in Austin, Texas, alongside the rise of agentic robotics — a new paradigm that integrates frontier agents to create interpretable code for physical robotics systems.</span></p>
<p><span style="font-weight: 400;">At CoRL, NVIDIA is introducing new open robotics technologies, including </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/world-action-model/"><span style="font-weight: 400;">world action models</span></a><span style="font-weight: 400;">, simulation tools, benchmarks and agentic workflows. </span></p>
<p><span style="font-weight: 400;">Two NVIDIA papers are among six finalists out of thousands of submissions for the Best Paper Awards at CoRL: </span></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><a target="_blank" href="https://research.nvidia.com/labs/dair/grail/"><span style="font-weight: 400;">GRAIL</span></a><span style="font-weight: 400;"> (Generating Humanoid Loco-Manipulation from World Models), which presents a digital generation pipeline for 3D assets and simulator-ready scenes for robot learning.</span></li>
<li style="font-weight: 400;" aria-level="1"><a target="_blank" href="https://research.nvidia.com/labs/gear/robottt/"><span style="font-weight: 400;">RoboTTT: Context Scaling for Robot Policies</span></a><span style="font-weight: 400;">, which introduces a robot model and training recipe that scales visuomotor context three orders of magnitude beyond state-of-the-art policies without growing inference latency.</span></li>
</ul>
<p><span style="font-weight: 400;">These advancements help researchers train robots on complex tasks, evaluate their performance across changing conditions and use failures to guide further learning — building the precision, adaptability and autonomy needed to move from lab demonstrations to industrial deployment. </span></p>
<p><span style="font-weight: 400;">NVIDIA is working with partners like </span><a target="_blank" href="https://www.ambirobotics.com/"><span style="font-weight: 400;">Ambi Robotics</span></a><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Bosch Research</span><span style="font-weight: 400;">, </span><a target="_blank" href="https://www.dexmate.com/blog/an-anatomy-of-coding-agents-tackling-robotics-tasks"><span style="font-weight: 400;">Dexmate</span></a><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Dyna Robotics</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">FieldAI</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Flexion</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Noitom Robotics</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Siemens</span><span style="font-weight: 400;">, </span><a target="_blank" href="http://skild.ai/blogs/steel-solver"><span style="font-weight: 400;">Skild AI</span></a><span style="font-weight: 400;">, </span><span style="font-weight: 400;">RLWRLD</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">UC Berkeley</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">Walden Robotics</span><span style="font-weight: 400;"> and </span><span style="font-weight: 400;">the University of Washington</span><span style="font-weight: 400;"> to bring these advancements to the broader robotics community.  </span></p>
<h2><b>World Action Models Enable Next Level of Robot Autonomy</b></h2>
<p><span style="font-weight: 400;">The next level of robot autonomy requires robots to perceive their surroundings, anticipate how their actions will change the environment and execute complex, multistep tasks with a high degree of precision. World action models enable exactly that.</span></p>
<p><span style="font-weight: 400;">At CoRL, NVIDIA is introducing </span><a target="_blank" href="https://research.nvidia.com/labs/gear/gr00t-2"><span style="font-weight: 400;">GR00T 2</span></a><span style="font-weight: 400;">, an open frontier world action model built on NVIDIA Cosmos. Trained on diverse robot and human data, including 100,000 hours of </span><a target="_blank" href="https://huggingface.co/spaces/nvidia/PhysicalAI-Human-1M-Explorer"><span style="font-weight: 400;">NVIDIA open source human egocentric data</span></a><span style="font-weight: 400;">, the model enables robots to learn dexterous manipulation skills. Key features include:</span></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><b>Out-of-the-box performance:</b><span style="font-weight: 400;"> Completed 40 of 50 evaluated tasks at least once without task-specific demonstrations.</span></li>
<li style="font-weight: 400;" aria-level="1"><b>Skill transfer:</b><span style="font-weight: 400;"> Learns from human demonstrations and transfers skills between different robot bodies without robot demonstrations</span></li>
<li style="font-weight: 400;" aria-level="1"><b>Generalization with little data:</b><span style="font-weight: 400;"> Achieved 71% average success across 50 tasks with just one demonstration per task, increasing to 95% with five.</span></li>
<li style="font-weight: 400;" aria-level="1"><b>Agent control:</b><span style="font-weight: 400;"> AI agents can use GR00T 2’s application programming interface and supporting tools to run skills in sequence and recover from errors.</span></li>
</ul>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-1" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/groot-2-shipping-label.mp4?_=1" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/groot-2-shipping-label.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/groot-2-shipping-label.mp4</a></video></div>
<p>&nbsp;</p>
<p><span style="font-weight: 400;">GR00T 2 currently ranks among the top three models across all vision language action and world action model categories for the RoboCasa365, RoboLab, RoboDojo and MolmoSpaces benchmarks, with multiple leaderboard wins.  </span></p>
<p><span style="font-weight: 400;">Nexuni</span><span style="font-weight: 400;"> is testing it for robotic laundry handling, </span><span style="font-weight: 400;">Foxconn</span><span style="font-weight: 400;"> is applying GR00T 2 to factory automation for server manufacturing and </span><span style="font-weight: 400;">Siemens</span><span style="font-weight: 400;"> is evaluating it across industrial use cases.</span></p>
<p><span style="font-weight: 400;">MicroAGI</span><span style="font-weight: 400;"> is using GR00T 2, post-trained through reinforcement learning, to perform Ethernet cable swapping with a YAM robotic arm. Its agentic robotics approach automates the creation and calibration of simulation environments using Isaac Lab 3.0 and Newton, where the policy is trained.</span></p>
<p><span style="font-weight: 400;">Training capable robots requires diverse data. Open NVIDIA workflows and models equip researchers with better tools for data collection and annotation:</span></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">For researchers building robot-training datasets, NVIDIA’s new open Video to Data workflow turns human video into simulated robot demonstrations, with a </span><a target="_blank" href="https://nvidia-isaac.github.io/video_to_data/v2d_challenge/"><span style="font-weight: 400;">challenge</span></a><span style="font-weight: 400;"> inviting researchers to advance it.</span></li>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">The </span><a target="_blank" href="https://huggingface.co/nvidia/EgoHand-v1"><span style="font-weight: 400;">NVIDIA EgoHand open model</span></a><span style="font-weight: 400;"> — being demoed at CoRL and with over 40,000 </span><span style="font-weight: 400;">Hugging Face</span><span style="font-weight: 400;"> downloads in the two weeks since launch — reconstructs 3D hand motion, trained with data from </span><span style="font-weight: 400;">Noitom Robotics</span><span style="font-weight: 400;">.</span></li>
</ul>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-2" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/egohand-demo.mp4?_=2" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/egohand-demo.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/egohand-demo.mp4</a></video></div>
<p>&nbsp;</p>
<h2><b>Where the Training and Scaling Happens — in Simulation</b></h2>
<p><span style="font-weight: 400;">A pretrained model gives robots a core set of skills. Simulation lets researchers train, refine and evaluate skills at scale before deploying them on physical robots. </span></p>
<p><a target="_blank" href="https://developer.nvidia.com/isaac/lab"><span style="font-weight: 400;">NVIDIA Isaac Lab</span></a><span style="font-weight: 400;">, an open source robot-learning framework, provides the foundation for that work. Its latest release, </span><a target="_blank" href="https://github.com/isaac-sim/IsaacLab/releases/tag/v3.0.0"><span style="font-weight: 400;">Isaac Lab 3.0</span></a><span style="font-weight: 400;">, allows researchers to use agents to quickly set up training environments with </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/simready/"><span style="font-weight: 400;">simulation-ready assets</span></a><span style="font-weight: 400;">, switch between </span><a target="_blank" href="https://developer.nvidia.com/physx-sdk"><span style="font-weight: 400;">NVIDIA PhysX</span></a><span style="font-weight: 400;"> and </span><a target="_blank" href="https://developer.nvidia.com/newton-physics"><span style="font-weight: 400;">Newton physics solvers</span></a><span style="font-weight: 400;">, choose renderers for perception-based training and apply a new reinforcement post-training library to foundation models like GR00T.</span></p>
<p><a target="_blank" href="https://www.nvidia.com/en-us/use-cases/physics-simulation-for-robotics/"><span style="font-weight: 400;">Accurate physics</span></a><span style="font-weight: 400;"> is critical to transferring learned skills from simulation to the real robot. Tighter integration with Newton</span><span style="font-weight: 400;">, an open source physics engine, now allows Isaac Lab to model deformable objects such as cables and cloth, along with complex articulated systems such as robotic hands with many interacting joints. </span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-3" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-strawberry.mp4?_=3" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-strawberry.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-strawberry.mp4</a></video></div>
<p><em>Integration with Newton simulates how a strawberry deforms under a robot’s grip.</em></p>
<p><span style="font-weight: 400;">Together, Isaac Lab and Newton combine accurate physics with scale to enable researchers to train thousands of simulated robots in parallel. In a vision-based dexterous manipulation benchmark, Isaac Lab 3.0 with Newton achieved up to 2.5x the training throughput of Isaac Lab 2.3 with PhysX.</span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-4" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-physx-web.mp4?_=4" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-physx-web.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/newton-physx-web.mp4</a></video></div>
<p><i><span style="font-weight: 400;">Isaac Lab supports robot simulation with Newton and NVIDIA PhysX.</span></i></p>
<p><span style="font-weight: 400;">Developers are extending Newton’s capabilities. At CoRL, </span><a target="_blank" href="http://skild.ai/blogs/steel-solver"><span style="font-weight: 400;">Skild AI</span></a><span style="font-weight: 400;"> announced Scalable Throughput-optimized Engine for Embodied Learning, or STEEL, a new rigid-body physics solver built on Newton to accelerate robot training with Isaac Lab.</span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-5" width="1200" height="598" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/robotics-montage-8s.mp4?_=5" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/robotics-montage-8s.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/robotics-montage-8s.mp4</a></video></div>
<p><em><i><span style="font-weight: 400;">Skild AI’s STEEL Solver.</span></i></em></p>
<p><span style="font-weight: 400;">Flexion</span><span style="font-weight: 400;"> showcased how Isaac Lab and Newton help train Reflect, its robot-intelligence model combining reasoning and whole-body manipulation. </span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-6" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/flexion-newton-isaac-lab.mp4?_=6" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/flexion-newton-isaac-lab.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/flexion-newton-isaac-lab.mp4</a></video></div>
<p><i><span style="font-weight: 400;">Flexion uses Newton for RL with Isaac Lab.</span></i></p>
<p><span style="font-weight: 400;">FieldAI</span><span style="font-weight: 400;"> is using Newton — as well as Isaac Lab and Isaac Sim, built on NVIDIA Omniverse libraries — to train and validate robot policies for deployment in unstructured real-world environments. </span><span style="font-weight: 400;">Dyna Robotics</span><span style="font-weight: 400;"> will demonstrate how parallel simulation in Isaac Lab helps train whole-body controllers for its </span><a target="_blank" href="https://www.dyna.co/dyna-2.1"><span style="font-weight: 400;">semi-humanoid Taku robot</span></a><span style="font-weight: 400;"> for work in warehouses, hotels and food services.</span></p>
<p><span style="font-weight: 400;">Walden Robotics</span><span style="font-weight: 400;"> is using Isaac Sim’s photorealistic rendering to train and evaluate its general-purpose robot in virtual environments for manufacturing and logistics, while </span><a target="_blank" href="https://www.dexmate.com/blog/an-anatomy-of-coding-agents-tackling-robotics-tasks"><span style="font-weight: 400;">Dexmate</span></a><span style="font-weight: 400;"> is exploring how coding agents can rehearse and refine manipulation strategies in Isaac Sim before executing them on its Vega robot. </span></p>
<p><a target="_blank" href="https://alpha-nist.github.io/"><span style="font-weight: 400;">AlphaNIST</span></a><span style="font-weight: 400;">, built in Isaac Lab, demonstrates how efficient practice can translate into precision. A single policy learns all 20 tasks on the NIST Assembly Task Board, manipulating  millimeter-scale parts using only a yes-or-no success signal. It achieves more than 98% training success, compared with 81% for separate per-task policies, using roughly 39x less GPU time.</span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-7" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/alphanist-6-16s-web.mp4?_=7" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/alphanist-6-16s-web.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/alphanist-6-16s-web.mp4</a></video></div>
<p><i><span style="font-weight: 400;">AlphaNIST uses Isaac Lab to train a single robot policy across 20 precision tasks on the NIST Assembly Task Board. </span></i></p>
<p><span style="font-weight: 400;">Behind those results is </span><a target="_blank" href="https://sgs-rl.github.io/"><span style="font-weight: 400;">Success-Guided Sampling</span></a><span style="font-weight: 400;">, or SGS, from </span><span style="font-weight: 400;">the University of Washington</span><span style="font-weight: 400;"> and NVIDIA. The method focuses practice on tasks a policy succeeds at about half the time, directing training toward skills it’s still learning. With SGS, robot training can scale beyond a million parallel environments. </span></p>
<p><span style="font-weight: 400;">The </span><span style="font-weight: 400;">University of Texas at Austin’s School of Computing and Texas Robotics</span><span style="font-weight: 400;"> uses Isaac Sim and Isaac Lab to train robotic skills in simulation, letting students start developing before physical hardware is available.</span></p>
<h2><b>New Industrial Benchmarks for Robot Evaluation</b></h2>
<p><span style="font-weight: 400;">Learning a skill is one challenge. Performing it reliably across changing conditions is another. </span></p>
<p><a target="_blank" href="https://developer.nvidia.com/isaac/lab-arena"><span style="font-weight: 400;">NVIDIA Isaac Lab-Arena</span></a><span style="font-weight: 400;">, an open source framework for scaled policy evaluation, enables developers to compose diverse and repeatable evaluations, then run policies across thousands of variations in parallel. Analyses expose which conditions cause failures, so researchers know what to fix in their next training run. The developer preview of its latest version, 0.4, is arriving at CoRL. </span></p>
<p><span style="font-weight: 400;">DexBench and VABAR, two new open benchmarks, are among the first designed to measure robot dexterity and adaptability across industrial tasks using Isaac Lab-Arena and Newton.</span></p>
<p><a target="_blank" href="https://dexbench.ai/"><span style="font-weight: 400;">DexBench</span></a><span style="font-weight: 400;">, developed by </span><a target="_blank" href="https://www.rlwrld.ai/en"><span style="font-weight: 400;">RLWRLD</span></a><span style="font-weight: 400;"> in collaboration with NVIDIA, takes dexterity evaluation off the tabletop and into real-world workflows. Built using NVIDIA Isaac Lab-Arena, it features 15 tasks across four scenes spanning retail, logistics, manufacturing and hospitality, testing generalization across object, spatial and physics variations. </span></p>
<p><span style="font-weight: 400;">Genesis AI</span><span style="font-weight: 400;">, </span><span style="font-weight: 400;">mimic robotics</span><span style="font-weight: 400;"> and other industry partners are evaluating DexBench through early access.</span></p>
<p><span style="font-weight: 400;">Teams can run DexBench on <a target="_blank" href="https://docs.manifold.bifrost.ai/benchmarks/dexbench">Manifold</a>, </span><span style="font-weight: 400;">Bifrost’s</span><span style="font-weight: 400;"> evaluation platform for scaling robotics simulations, with no setup required, built-in failure analysis and free credits for initial evaluations. </span></p>
<p><a target="_blank" href="https://berkeleyautomation.github.io/vabar-website/"><span style="font-weight: 400;">VABAR</span></a><span style="font-weight: 400;"> — the Variational Automation Benchmark for Agentic Robotics — from </span><a target="_blank" href="https://news.berkeley.edu/2026/11/09/recent-advances-in-ai-are-creating-a-paradigm-shift-for-robotics/"><span style="font-weight: 400;">UC Berkeley</span></a><span style="font-weight: 400;"> and NVIDIA, evaluates robots across six industrial tasks. Each carries standardized variations, difficulty tiers and success metrics. </span></p>
<div style="width: 760px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-8" width="760" height="570" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/task-tool-sorting.mp4?_=8" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/task-tool-sorting.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/task-tool-sorting.mp4</a></video></div>
<p><i><span style="font-weight: 400;">A simulated tool-sorting task demonstrates how VABAR evaluates robot manipulation skills for industrial workflows.</span></i></p>
<h2><b>Agents Turn Skills Into Robot Programs</b></h2>
<p><span style="font-weight: 400;">Successful task completion requires robots to coordinate multiple skills and adapt when something goes wrong. Building reliable programs for these multistep tasks remains a challenge.</span></p>
<p><span style="font-weight: 400;">Agentic robotics helps solve that challenge.</span></p>
<p><span style="font-weight: 400;">UC Berkeley’s</span><a target="_blank" href="https://graph-robots.github.io/gap/"><span style="font-weight: 400;"> new </span><span style="font-weight: 400;">Graph-as-Policy</span></a><span style="font-weight: 400;"> (GaP) framework uses agents to connect individual skills into robot programs. Agents test these programs using NVIDIA Isaac open simulation technologies and refine them based on failures. This helps researchers scale development with less data while keeping the programs interpretable for engineers to review and verify before deployment.</span></p>
<div style="width: 960px;" class="wp-video"><video class="wp-video-shortcode" id="video-99751-9" width="960" height="600" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/wipe-the-bar.mp4?_=9" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/wipe-the-bar.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/wipe-the-bar.mp4</a></video></div>
<p><i><span style="font-weight: 400;">GaP uses agents and simulation to turn individual robot skills into coordinated actions, such as wiping a bar.</span></i></p>
<p><span style="font-weight: 400;">“To me, agentic robotics is the most exciting technological development since the internet in 1995,” said Ken Goldberg, professor of robotics at UC Berkeley and a lead on the VABAR and GaP projects.</span></p>

<h2><b>Samsung</b><b> Advances Semiconductor Engineering With Accelerated Computing and AI Physics</b></h2>
<p><span style="font-weight: 400;">Samsung Electronics</span><span style="font-weight: 400;"> is <a target="_blank" href="https://semiconductor.samsung.com/news-events/tech-blog/samsung-showcases-ai-driven-semiconductor-engineering-research-and-collaboration-with-nvidia-at-nvidia-ai-day-seoul-2026/">expanding its collaboration with NVIDIA</a> to advance semiconductor innovation through accelerated computing and AI physics. The work spans materials research, process development and device engineering.</span></p>
<p><span style="font-weight: 400;">In technology computer-aided design, </span><span style="font-weight: 400;">Samsung</span><span style="font-weight: 400;"> is working with </span><a target="_blank" href="https://nvidianews.nvidia.com/news/nvidia-expands-nvidia-agent-toolkit-with-nvidia-physicsnemo-and-cuda-x-libraries-to-transform-how-the-world-engineers-designs-and-builds"><span style="font-weight: 400;">NVIDIA cuISS</span></a><span style="font-weight: 400;"> and </span><a target="_blank" href="https://developer.nvidia.com/cudss"><span style="font-weight: 400;">NVIDIA cuDSS</span></a><span style="font-weight: 400;"> to accelerate computations involving sparse linear systems. The collaboration also extends to GPU acceleration for process and optical simulations. In materials research, Samsung’s sMOL platform has run selected quantum chemical calculations up to 5x faster end to end with</span> <a target="_blank" href="https://docs.nvidia.com/cuda/cuest/"><span style="font-weight: 400;">NVIDIA cuEST</span></a><span style="font-weight: 400;">. <p><span style="font-weight: 400;">Samsung</span><span style="font-weight: 400;"> is developing chip-scale thermal and mechanical analysis workflows with</span> <a target="_blank" href="https://developer.nvidia.com/physicsnemo"><span style="font-weight: 400;">NVIDIA PhysicsNeMo</span></a><span style="font-weight: 400;">. In one AI homogenization case, combining AI-predicted effective material properties, coarser grids and GPU acceleration resulted in a roughly 1,600x speedup. Simulation time fell from about 18 hours for a fine-grid solve on a 32-core CPU to 41 seconds for a GPU-accelerated coarse-grid solve.</span></p>
<p><span style="font-weight: 400;">Looking ahead,</span> <a target="_blank" href="https://nvidianews.nvidia.com/news/nvidia-expands-nvidia-agent-toolkit-with-nvidia-physicsnemo-and-cuda-x-libraries-to-transform-how-the-world-engineers-designs-and-builds"><span style="font-weight: 400;">NVIDIA Agent Toolkit</span></a><span style="font-weight: 400;"> could connect these simulation tools and AI models, helping future engineering agents run analyses and compare design options.</span></p>

		<dc:creator><![CDATA[Soma Velayutham]]></dc:creator>
		<pubDate>Fri, 06 Nov 2026 16:00:35 +0000</pubDate>
				<category><![CDATA[AI]]></category>

					<description><![CDATA[A year ago, NVIDIA open sourced its Aerial wireless software, joining Sionna and a broader suite of open source tools for accelerating next-generation 6G network development. 										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">A year ago, NVIDIA </span><a href="https://blogs.nvidia.com/blog/open-source-aerial-ai-native-6g/"><span style="font-weight: 400;">open sourced its Aerial wireless software</span></a><span style="font-weight: 400;">, joining Sionna and a broader suite of open source tools for accelerating next-generation 6G network development. Together, they give researchers a foundation for testing ideas, comparing results and building on each other’s work — connecting simulation and AI training with experiments on real over-the-air wireless systems.</span></p>
<p><span style="font-weight: 400;">Today, researchers and developers are using these tools to build 6G-ready networks that do more than just transmit data — receiving signals more effectively, keeping robots and autonomous systems connected when it matters most, and adapting in real time as devices move through the world.</span></p>
<p><span style="font-weight: 400;">Over the past year, global developer adoption of </span><a target="_blank" href="https://developer.nvidia.com/topics/telecommunications/ai-aerial?size=n_6_n"><span style="font-weight: 400;">NVIDIA AI Aerial</span></a><span style="font-weight: 400;"> and </span><a target="_blank" href="https://github.com/nvlabs/sionna"><span style="font-weight: 400;">NVIDIA Sionna</span></a><span style="font-weight: 400;"> software has grown 10x, while NVIDIA’s open source 5G/6G tools have surpassed 1 million downloads. More than 8,000 research and academic institutions worldwide are using these platforms. </span></p>
<p><span style="font-weight: 400;">The projects emerging today offer a view of how future networks could look. Each addresses a different challenge, but together point toward a broader ambition for building AI-native 6G networks that deliver connectivity, computing and sensing over a converged software-defined platform for billions of people, machines and agents.</span></p>
<h2><b>Networks That Help Robots React Faster</b></h2>
<p><span style="font-weight: 400;">A robot picking up an object needs to understand its surroundings and act before they change. When the AI powering that decision runs on a nearby server or in the cloud, the wireless connection becomes part of the response time. </span></p>
<p><span style="font-weight: 400;">Researchers are exploring a more efficient approach called goal-oriented semantic communications. Instead of sending full images, robots transmit compact descriptions of objects, their positions and their relationships. Transmitting just as much information as needed allows robots to more quickly respond, especially in dynamic environments like workplaces and warehouses.</span></p>
<p><span style="font-weight: 400;">At </span><a target="_blank" href="https://arxiv.org/html/2609.15895"><span style="font-weight: 400;">King’s College London</span></a><span style="font-weight: 400;">, researchers connected a camera-equipped robot arm to an </span><a target="_blank" href="https://www.nvidia.com/en-us/autonomous-machines/embedded-systems/jetson-orin/"><span style="font-weight: 400;">NVIDIA Jetson AGX Orin</span></a><span style="font-weight: 400;"> running NVIDIA Sionna, which supports both software-defined 5G network and edge AI processing. In fruit-packing and cube-stacking experiments with deliberately introduced faults, the approach reduced robot task completion time by up to </span>52.6%<span style="font-weight: 400;"> and improved task success compared with sending periodic images.</span></p>
<p><span style="font-weight: 400;">In addition to quicker responses and less processing overhead, the system also proved more resilient — detecting dropped objects, recovering from unsuccessful actions and, in configurations using a digital twin, checking planned movements for potential collisions before execution. </span></p>
<h2><b>Networks That Learn to Receive Signals Better</b></h2>
<p><span style="font-weight: 400;">For a firefighter receiving live drone footage or a rescue team searching for a missing person, timely images can help guide urgent decisions. But interference and changing radio conditions can make wireless signals harder to decode, causing errors and retransmissions that delay information from the field.</span></p>
<p><span style="font-weight: 400;">AI receivers address this challenge by learning to recover information from incoming signals more effectively. Better reception could help responders maintain a clearer, more current view of a fire scene or search area.</span></p>
<p><a target="_blank" href="https://www.softbank.jp/en/corp/technology/research/topics/238/?adid=nvblog"><span style="font-weight: 400;">SoftBank</span></a><span style="font-weight: 400;"> demonstrated this by integrating a neural receiver into </span><a target="_blank" href="https://github.com/NVIDIA/aerial-cuda-accelerated-ran"><span style="font-weight: 400;">NVIDIA Aerial CUDA-Accelerated RAN (ACAR)</span></a><span style="font-weight: 400;"> and testing it with a commercial 5G smartphone. In controlled tests with interference, the neural receiver delivered higher uplink throughput than a conventional receiver at all 15 tested settings, with a maximum gain of roughly </span>60%<span style="font-weight: 400;">.</span></p>
<p><span style="font-weight: 400;">Another way to improve reception is to teach receivers about the environments where they operate. Using NVIDIA Aerial Testbed, </span><a target="_blank" href="https://arxiv.org/html/2609.04004"><span style="font-weight: 400;">ETH Zurich</span></a><span style="font-weight: 400;"> researchers found that tuning neural receivers using local measurements reduced block error rates by more than one-third compared with selected pretrained versions. </span></p>
<h2><b>Networks That Learn When to Save Power</b></h2>
<p><span style="font-weight: 400;">As 6G connects more devices and supports more AI applications, managing energy demand will become increasingly important. </span></p>
<p><span style="font-weight: 400;">For example, a network may need enough capacity to serve a busy stadium, but demand changes when the crowd leaves. AI can help identify when spare capacity can power down — and when it needs to come back online — so operators can reduce electricity use without dropping connections.</span></p>
<p><span style="font-weight: 400;">At the </span><a target="_blank" href="https://eprints.whiterose.ac.uk/id/eprint/242057/1/Accepted_Network_in_a_box__ICC_2026_Yejing.pdf"><span style="font-weight: 400;">University of Leeds</span></a><span style="font-weight: 400;">, researchers developed a system that predicts network demand 10 minutes ahead and uses those forecasts to guide base station sleep decisions. Before powering down, it checks that neighboring active stations can continue serving affected devices and monitors for changes that require capacity to be restored.</span></p>
<p><span style="font-weight: 400;">The team tested their approach using a portable, </span><a target="_blank" href="https://www.nvidia.com/en-us/products/workstations/dgx-spark/"><span style="font-weight: 400;">NVIDIA DGX Spark</span></a><span style="font-weight: 400;">-powered 5G “network-in-a-box” alongside a digital twin for validating decisions against real wireless equipment. The result: researchers reported a 45.6% reduction in RAN power consumption relative to a full-power baseline while maintaining device connectivity.</span></p>
<h2><b>Networks That Can Be Tested Faster — Before They’re Built</b></h2>
<p><span style="font-weight: 400;">Before deploying a network, researchers need to know how it will perform when hundreds of devices compete for connections or radio signals run into interference. Simulating these conditions helps teams evaluate designs before committing to costly equipment and field trials. But realistic simulations can take hours, limiting how many ideas researchers can explore.</span></p>
<p><span style="font-weight: 400;">The </span><a target="_blank" href="https://www.cttc.cat/cttc-accelerates-5g-network-simulation-from-hours-to-minutes-with-nvidia/"><span style="font-weight: 400;">Centre Tecnològic de Telecomunicacions de Catalunya (CTTC)</span></a><span style="font-weight: 400;"> is accelerating that process by bringing GPU-accelerated radio channel models, running on ACAR, into CTTC’s open source 5G-LENA network simulator. These models calculate how wireless signals travel between antennas and devices — a computation that grows increasingly demanding as simulated networks grow.</span></p>
<p><span style="font-weight: 400;">In an early evaluation, the approach reduced simulation runtime from approximately three hours to 10-20 minutes, depending on the integration, while preserving the expected statistical behavior and network performance.</span></p>
<p><span style="font-weight: 400;">Faster simulations let researchers compare more designs, investigate more demanding scenarios and refine ideas sooner. As the industry develops 6G, this could shorten the path from a proposed innovation to a thoroughly evaluated network design — helping teams build better connectivity before deploying it in the real world.</span></p>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">AI agents do more than generate answers. They search for information, query databases, write and test code and take action. </span></p>
<p><span style="font-weight: 400;">Each of those steps relies on a CPU, with agents moving between GPU reasoning and CPU execution throughout a task. </span></p>
<p><span style="font-weight: 400;">As businesses put more agents to work, AI factories need CPUs that can execute those steps quickly and support many agents at once, all within the limits of available power.</span></p>
<p><b>What this means:</b><span style="font-weight: 400;"> AI infrastructure providers need to support more agents without making each one wait longer to get work done. And critically, AI factories are power limited. This means operators need to choose infrastructure that maximizes the work done for every watt. </span></p>
<p><b>Why it matters:</b> <a target="_blank" href="https://www.nvidia.com/en-us/data-center/vera-cpu/"><span style="font-weight: 400;">NVIDIA Vera</span></a><span style="font-weight: 400;"> delivers both fast agent performance and high capacity per watt within a single CPU. That gives providers one CPU for a range of agent workloads, rather than having to mix and match fast and dense x86 parts to balance speed and capacity.</span></p>
<p><b>The data that proves it:</b><span style="font-weight: 400;"> In a 100-megawatt data center comparison, NVIDIA found that a single Vera CPU performs better than the fastest x86 CPU and the most energy-efficient x86 CPU.</span></p>
<ul>
<li><span style="font-weight: 400;">Vera delivers industry-leading agent speed while enabling </span><b>1.6x more agents per watt </b><span style="font-weight: 400;">versus the fastest x86 CPU.</span></li>
<li><span style="font-weight: 400;">Vera delivers </span><b>2x faster agent speed</b><span style="font-weight: 400;"> with leading energy efficiency compared with the most energy-efficient x86 CPU.</span></li>
</ul>
<p><span style="font-weight: 400;">Partners are already putting Vera to work. Early adopters see the same exceptional performance in production-style tests:</span></p>
<ul>
<li><a target="_blank" href="https://www.perplexity.ai/en-GB/hub/blog/secure-sandboxes-for-agents"><span style="font-weight: 400;">Perplexity</span></a><span style="font-weight: 400;">: Ran agentic coding tasks 1.5x faster with Vera than on traditional CPUs. Perplexity plans to deploy Vera in an upcoming production system.</span></li>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">Turning a simulation idea into a working application means assembling assets, connecting physics and rendering, and checking that the scene behaves as intended. Developers are combining frontier AI models with</span><a target="_blank" href="https://developer.nvidia.com/omniverse"> <span style="font-weight: 400;">NVIDIA Omniverse libraries</span></a><span style="font-weight: 400;"> to help carry out that work — building applications for exploring scenarios, investigating failures and improving designs.</span></p>
<p><span style="font-weight: 400;">Developers direct AI agents through natural-language instructions, review results and guide changes. Omniverse libraries provide GPU-accelerated physics, rendering and sensor simulation capabilities.</span></p>

<h2 id="editable-assets" class="wp-block-heading" style="font-size: 24px;"><b>Create Editable 3D Assets With Houdini and AI Agents </b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#editable-assets"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<p><span style="font-weight: 400;">Creating animated 3D content requires connecting modeling, simulation, materials and rendering. Nick Scarcella, a senior technical artist on NVIDIA’s BondLab team, directed AI agents — primarily using Claude — to work with CUDA libraries and Isaac Sim to create animations. The BondLab team uses</span><a target="_blank" href="https://www.sidefx.com/products/houdini/"> <span style="font-weight: 400;">SideFX Houdini</span></a><span style="font-weight: 400;"> and the</span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx"> <span style="font-weight: 400;">NVIDIA ovrtx library</span></a><span style="font-weight: 400;"> to develop materials, lighting and the final rendered appearance.</span></p>

<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-98677-13" width="1200" height="675" autoplay preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/10/Turbine-Lab-RTX-and-What-If-under-10MB-1.mp4?_=13" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/10/Turbine-Lab-RTX-and-What-If-under-10MB-1.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/10/Turbine-Lab-RTX-and-What-If-under-10MB-1.mp4</a></video></div>

<p><span style="font-weight: 400;">Before changing how industrial equipment operates, engineers need a way to explore the consequences. Pradeep Kaushik, a member of the NVIDIA Omniverse developer relations team, directed Astra to build a what-if analysis application around a simulated gas turbine and generator.</span></p>
<p><span style="font-weight: 400;">The application lets users adjust conditions such as load, ambient temperature and fuel composition, then compare power, efficiency, fuel consumption and equipment response. Six test procedures explore scenarios including load changes, a stuck fuel valve and an exhaust-sensor error.</span></p>
<p><span style="font-weight: 400;">The prototype gives engineers an interactive way to investigate how operating changes and faults could affect equipment behavior, supporting decisions about which scenarios warrant further testing.</span></p>
<p><span style="font-weight: 400;">Astra used tools like Cantera for thermochemistry and SciPy for equipment dynamics. The application maps solver results to rotor animation and color-coded temperature, pressure and flow-velocity indicators in a 3D turbine. NVIDIA Omniverse libraries update the scene (</span><a target="_blank" href="https://github.com/nvidia-omniverse/ovstage"><span style="font-weight: 400;">ovstage</span></a><span style="font-weight: 400;">), render it with RTX (ovrtx) and stream the view to the browser (ovstream). Engineers can rotate and zoom the cutaway, switch between indicators, and pause or scrub through a simulated response alongside charts and virtual instruments.</span></p>

<h2 id="warehouse" class="wp-block-heading" style="font-size: 24px;"><b>Stress-Test a Warehouse Simulation at Scale </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#warehouse"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-98677-15" width="1200" height="675" autoplay preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/10/Infra-scale-demo-20260914_144614-Meeting-Recording.mp4?_=15" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/10/Infra-scale-demo-20260914_144614-Meeting-Recording.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/10/Infra-scale-demo-20260914_144614-Meeting-Recording.mp4</a></video></div>
<p>&nbsp;</p>
<p><span style="font-weight: 400;">A warehouse simulation needs to keep running smoothly as more robot arms, conveyors and boxes fill the scene. </span></p>
<p><span style="font-weight: 400;">When it slows down, developers need to identify what’s holding it back. </span><span style="font-weight: 400;">Bhavik Sanganee, principal engineer at NVIDIA, used Astra with </span><a target="_blank" href="https://developer.nvidia.com/omniverse?size=n_12_n&amp;sort-field=featured&amp;sort-direction=desc"><span style="font-weight: 400;">NVIDIA Omniverse libraries</span></a><span style="font-weight: 400;"> to build a warehouse simulation, increase its complexity and investigate slowdowns.</span></p>
<p><span style="font-weight: 400;">Performance first fell below the target when the scene doubled in size. Running physics calculations, image rendering and video preparation concurrently restored performance and enabled further scaling.</span></p>
<p><span style="font-weight: 400;">With 80 conveyors, 40 arms and 800 boxes, the simulation sustained 30 frames per second at full HD resolution during a two-minute test. The arms completed 640 successful box placements.</span></p>
<p><span style="font-weight: 400;">Doubling the scene again reduced performance. Testing traced the slowdown to the physics and robot-control pipeline, giving Sanganee a specific area to improve.</span></p>
<p><em><span style="font-weight: 400;">Start building with </span><a target="_blank" href="https://developer.nvidia.com/omniverse?size=n_12_n&amp;sort-field=featured&amp;sort-direction=desc"><span style="font-weight: 400;">NVIDIA Omniverse libraries</span></a><span style="font-weight: 400;">.</span></em></p>

<p><span style="font-weight: 400;">Oyindamola Omotuyi, robotics technical marketing manager at NVIDIA, directed Astra to build a robot simulation using </span><a target="_blank" href="https://developer.nvidia.com/isaac/lab"><span style="font-weight: 400;">NVIDIA Isaac Lab</span></a><span style="font-weight: 400;">, </span><a target="_blank" href="https://developer.nvidia.com/newton-physics"><span style="font-weight: 400;">Newton</span></a><span style="font-weight: 400;"> physics and Omniverse rendering with a</span><a target="_blank" href="https://www.youtube.com/watch?v=K2ui16FdLZw"> <span style="font-weight: 400;">Robotiq gripper</span></a><span style="font-weight: 400;"> handling the cable.</span></p>
<p><span style="font-weight: 400;">Astra also developed a</span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/reinforcement-learning/"> <span style="font-weight: 400;">reinforcement learning</span></a><span style="font-weight: 400;"> system that combined learned cable-routing movements with position-and-orientation feedback and corrective adjustments for USB-C insertion. The simulation gave Omotuyi a way to test cable handling and connector alignment before moving to physical-robot experiments.</span></p>
<p><span style="font-weight: 400;">The controller used information supplied directly by the simulation. Next steps include testing a friction-held grasp and using information a physical robot could obtain from cameras and sensors.</span></p>

<h2 id="cad" class="wp-block-heading" style="font-size: 24px;"><b>Turn Robot Computer-Aided Design Into a SimReady Asset </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#cad"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<p><span style="font-weight: 400;">Before testing whether a robot can pick up and move a box, developers need a simulation model with joints that move correctly and with grippers that can hold the object. A computer-aided design (CAD) model provides the robot’s shape, but it still needs physics properties to perform the task.</span></p>
<p><span style="font-weight: 400;">Using an ABB Robotics YuMi robot, developers directed Astra with NVIDIA Omniverse content libraries to convert CAD files into OpenUSD, match the robot’s appearance to reference images, and configure joints and collision geometry. They checked the asset against SimReady Foundation requirements before testing it in NVIDIA Isaac Sim.</span></p>
<p><span style="font-weight: 400;">Both arms and grippers completed four cube pick-and-place cycles, using simulated finger contact and friction. These tests demonstrated behavior under the simulated conditions — estimated physical properties were not calibrated against the real robot.<br />
</span></p>

<p><em><span style="font-weight: 400;">Explore a gamified, physics-based control of a humanoid robot in first- and third-person view.</span></em><i></i></p>
<p><span style="font-weight: 400;">Before automating warehouse tasks, developers need an interactive simulation environment to explore task behavior and evaluate how the work gets done. Frank DeLise, Omniverse product manager at NVIDIA, used Astra to turn a </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/simready/"><span style="font-weight: 400;">SimReady</span></a><span style="font-weight: 400;"> warehouse and humanoid robot into an interactive simulator with first- and third-person views.</span></p>
<p><span style="font-weight: 400;">DeLise directed Astra to connect</span><a target="_blank" href="https://developer.nvidia.com/omniverse"> <span style="font-weight: 400;">NVIDIA Omniverse libraries</span></a><span style="font-weight: 400;"> for physics (</span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/PhysX/blob/main/ovphysx/README.md"><span style="font-weight: 400;">ovphysx</span></a><span style="font-weight: 400;">), scene updates (</span><a target="_blank" href="https://github.com/nvidia-omniverse/ovstage"><span style="font-weight: 400;">ovstage</span></a><span style="font-weight: 400;">), rendering (</span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx"><span style="font-weight: 400;">ovrtx</span></a><span style="font-weight: 400;">) and the user interface (</span><a target="_blank" href="https://github.com/NVIDIA-omniverse/ovui"><span style="font-weight: 400;">ovui</span></a><span style="font-weight: 400;">). He also used Astra with SimReady (</span><a target="_blank" href="https://github.com/nvidia/simready-foundation"><span style="font-weight: 400;">simready-foundation</span></a><span style="font-weight: 400;">) to create the physical scene in simulation. Astra then generated animation and application code to bring those capabilities together.</span></p>
<p><i><span style="font-weight: 400;">Learn how to </span></i><a target="_blank" href="https://developer.nvidia.com/blog/5-steps-to-create-simready-assets-for-robotics-with-frontier-ai-models/"><i><span style="font-weight: 400;">prepare and validate SimReady robot assets</span></i></a><i><span style="font-weight: 400;"> with frontier AI models and NVIDIA Omniverse libraries.</span></i></p>
<hr />
<p>&nbsp;</p>
<h2 id="autonomous-driving-testing" class="wp-block-heading" style="font-size: 24px;"><b>Connect an Autonomous-Driving Testing Workflow </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#autonomous-driving-testing"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-98677-18" width="1200" height="675" autoplay preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/10/zero-to-alpamayo-under-10MB.mp4?_=18" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/10/zero-to-alpamayo-under-10MB.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/10/zero-to-alpamayo-under-10MB.mp4</a></video></div>
<p>&nbsp;</p>
<p><span style="font-weight: 400;">Changing a scene, sensor or driving model can significantly affect autonomous-vehicle simulations. Doyub Kim, a manager on the simulation technology team at NVIDIA, asked Astra to build Zero to Alpamayo — a reusable simulation environment based on San Francisco’s Market Street.</span></p>
<p><span style="font-weight: 400;">Kim directed Astra to map out the workflow, then connect asset creation, traffic, </span><a target="_blank" href="https://developer.nvidia.com/blog/integrate-nvidia-omniverse-rtx-sensor-simulation-into-existing-apps/"><span style="font-weight: 400;">Omniverse RTX sensor simulation</span></a><span style="font-weight: 400;"> and </span><a target="_blank" href="https://www.nvidia.com/en-us/solutions/autonomous-vehicles/alpamayo/"><span style="font-weight: 400;">Alpamayo driving</span></a><span style="font-weight: 400;"> in stages, checking each integration. The resulting prototype was a testing ground for comparing models and tracing how scene or sensor changes affect downstream driving behavior. A separate Cosmos3-Nano experiment varied weather and lighting in recorded simulation videos, allowing Kim to compare the driving model’s responses to the same scenario under different conditions.</span></p>
<hr />
<p>&nbsp;</p>
<h2 id="sensor-differences" class="wp-block-heading" style="font-size: 24px;"><b>Use Sensor Differences to Create and Improve Digital Twins </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#sensor-differences"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-98677-19" width="1200" height="675" autoplay preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/10/0_00-0_004-hubble_rivermark_Real_Sim_no_loop.mp4?_=19" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/10/0_00-0_004-hubble_rivermark_Real_Sim_no_loop.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/10/0_00-0_004-hubble_rivermark_Real_Sim_no_loop.mp4</a></video></div>
<p><i><span style="font-weight: 400;">Comparing recorded and simulated camera and lidar outputs gives developers key performance indicator-based feedback for refining a scene.</span></i></p>
<p><span style="font-weight: 400;">To test robots and autonomous vehicles, developers need to know how closely simulated sensors match real ones. Ashley Reid, who works on RTX sensor validation at NVIDIA, directed Astra and Claude Fable 5 agents to compare </span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx"><span style="font-weight: 400;">ovrtx</span></a><span style="font-weight: 400;"> camera and raw LiDAR outputs with recorded data. The agents created two digital twins from scratch and improved two existing ones.</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;">Over about three days, Reid guided an iterative workflow in which agents measured differences, created or modified OpenUSD scenes, and checked the results. Changes addressed missing objects, geometry and materials, with acceptance depending on camera and LiDAR metrics. This gives developers a way to use measured discrepancies to guide scene creation and improvement.</span></p>
<p><i><span style="font-weight: 400;">Start by rendering an OpenUSD scene with the </span></i><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx/tree/main/examples/python/minimal"><i><span style="font-weight: 400;">ovrtx minimal Python example</span></i></a><i><span style="font-weight: 400;">, then define a sensor measure to compare with recorded data.</span></i></p>

<p>&nbsp;</p>
<h2 id="robo-olympics" class="wp-block-heading" style="font-size: 24px;"><b>Robo Olympics: Test Robot Skills With Simulation </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#robo-olympics"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<p><span style="font-weight: 400;">Teaching robots new movements means checking whether those actions work under physical constraints. Tae Kim, who leads NVIDIA Omniverse engineering and product, used sports videos and natural-language instructions to guide Astra in building Robo Olympics, an experimental project that tests simulated Unitree G1 humanoids performing sports movements.</span></p>
<p><span style="font-weight: 400;">Under Kim’s direction, Astra built controllers and refined them through physics trials. </span><a target="_blank" href="https://developer.nvidia.com/newton-physics"><span style="font-weight: 400;">Newton Physics Engine</span></a><span style="font-weight: 400;"> simulated behavior, the open source </span><a target="_blank" href="https://developer.nvidia.com/warp-python"><span style="font-weight: 400;">NVIDIA Warp</span></a><span style="font-weight: 400;"> framework accelerated calculations and </span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx"><span style="font-weight: 400;">ovrtx</span></a><span style="font-weight: 400;"> rendered scenes and virtual-camera images. In one experiment, the robot cleared a single hurdle in 64 of 100 simulation trials. The trials gave Kim feedback for improving the robot’s timing and control.</span></p>
<p><i><span style="font-weight: 400;">Watch Kim </span></i><a target="_blank" href="https://www.youtube.com/watch?v=pbwlRzjLwqc"><i><span style="font-weight: 400;">explore building simulations</span></i></a><i><span style="font-weight: 400;"> with Astra and NVIDIA Omniverse libraries.</span></i></p>

<h2 id="international-space-station" class="wp-block-heading" style="font-size: 24px;"><b>Bring the International Space Station Into the Browser </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#international-space-station"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<p><span style="font-weight: 400;">Turning 3D models into an application requires connecting assets, live data and an interface. Nic Johns, an engineering director at NVIDIA, prompted Astra to assemble NASA assets into an </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/openusd/"><span style="font-weight: 400;">OpenUSD</span></a><span style="font-weight: 400;"> International Space Station model with telemetry. Johns built the application with a single prompt, then used a follow-up prompt to shift the scene to Earth’s daytime side so the planet was visible.</span></p>
<p><span style="font-weight: 400;">The workflow used Blender for asset preparation and </span><a target="_blank" href="https://developer.nvidia.com/omniverse"><span style="font-weight: 400;">Omniverse libraries</span></a><span style="font-weight: 400;"> for rendering (</span><a target="_blank" href="https://github.com/NVIDIA-Omniverse/ovrtx"><span style="font-weight: 400;">ovrtx</span></a><span style="font-weight: 400;">), scene runtime (ovstage) and streaming (ovstream). The application brings 3D models and operational data into the browser, with Johns guiding its development through prompts and corrections.</span></p>
<p><i><span style="font-weight: 400;">Try the </span></i><a target="_blank" href="https://github.com/NVIDIA/skills/tree/main/skills/omniverse-realtime-viewer"><i><span style="font-weight: 400;">Omniverse Real-Time Viewer skill</span></i></a><i><span style="font-weight: 400;">.</span></i></p>

<h2 id="testing-environments" class="wp-block-heading" style="font-size: 24px;"><b>Turn Captured Rooms Into Testing Environments </b><b></b><a href="https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/#testing-environments"><b><img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f517.png" alt="🔗" class="wp-smiley" style="height: 1em; max-height: 1em;" /></b></a></h2>
<p><span style="font-weight: 400;">A digitally reconstructed room needs editable objects and accurate physical behavior before developers can test interactions. Chirag Majithia, from the Isaac engineering applications team at NVIDIA, directed Astra to turn stereo camera captures into an editable </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/openusd/"><span style="font-weight: 400;">OpenUSD</span></a><span style="font-weight: 400;"> studio.</span></p>
<p><span style="font-weight: 400;">The workflow combined PyCuSFM, FoundationStereo and nvblox for reconstruction, with user review guiding object selection and placement. Astra assembled generated and Blender-authored assets and used USD Content Agents to configure how objects move and interact in simulation. Isaac Sim tests guided collision and contact revisions for doors and drawers. The studio connects captured geometry to interaction testing, making gaps and object behavior easier to inspect. </span></p>

					<description><![CDATA[Chris Alexiuk has a simple rule about open source AI: If you believe in it, be loud about it. “We should be shouting about this technology from the rooftops,” said Alexiuk, a Toronto-based senior product research engineer in deep learning at NVIDIA who specializes in making open large language models (LLMs) practical for working developers.  [&#8230;]]]></description>
										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400">Chris Alexiuk has a simple rule about open source AI: If you believe in it, be loud about it.</span></p>
<p><span style="font-weight: 400">“We should be shouting about this technology from the rooftops,” said Alexiuk, a Toronto-based senior product research engineer in deep learning at NVIDIA who specializes in making open large language models (LLMs) practical for working developers. </span></p>
<p><span style="font-weight: 400">Alexiuk’s preferred “rooftop” is <a target="_blank" href="https://www.youtube.com/playlist?list=PL5B692fm6--vEL0FwctKghCpyEnBGAQJA">YouTube</a>, where he’s built a following teaching curious thousands how to build, fine-tune, evaluate and ship production LLM applications and agents. </span></p>
<p><span style="font-weight: 400">“I think the people who will most help us understand how to build and apply AI likely haven’t even heard of it yet,” he said. “Trying to get knowledge and information out to as many people as humanly possible is what continues to drive me.”</span></p>
<h2><b>Bringing NVIDIA Nemotron to Developers Everywhere</b></h2>
<p><span style="font-weight: 400">Having spent years teaching developers to build with open models, Alexiuk has concluded that transparency isn’t a feature of good AI; it’s the precondition for it.</span><span style="font-weight: 400"><br />
</span><span style="font-weight: 400"><br />
</span><span style="font-weight: 400">“Fully open source AI is necessary for the democratization of intelligence,” he said. “You should have access to the weights, the data that went into it, the training recipes, everything.”</span></p>
<p><span style="font-weight: 400">That’s why, on his LinkedIn profile, Alexiuk styles himself “No. 1 Nemotron Fan,” referring to the </span><a target="_blank" href="https://www.nvidia.com/en-us/ai-data-science/foundation-models/nemotron/"><span style="font-weight: 400">NVIDIA Nemotron</span></a><span style="font-weight: 400"> family of open source, multimodal models built for long-running, self-evolving and specialized AI agents.</span></p>
<p><span style="font-weight: 400">“I think Nemotron is the most important project that exists,” said Alexiuk, who also uses the pseudonym “Joe Nemotron” across social media. “I’m a firm believer that openness is a very important thing to undertake, so I’m going to be the No. 1 fan of whoever is doing that the best. And that is Nemotron.”</span></p>
<div style="width: 1200px;" class="wp-video"><video class="wp-video-shortcode" id="video-99663-20" width="1200" height="675" preload="metadata" controls="controls"><source type="video/mp4" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/ChrisAlexiuk_captions_9MB.mp4?_=20" /><a href="https://blogs.nvidia.com/wp-content/uploads/2026/11/ChrisAlexiuk_captions_9MB.mp4">https://blogs.nvidia.com/wp-content/uploads/2026/11/ChrisAlexiuk_captions_9MB.mp4</a></video></div>
<p>&nbsp;</p>
<p><span style="font-weight: 400">It’s this matter-of-fact directness and affable approachability that makes Alexiuk’s teaching style so appealing. On the social media platform X, he goes by the handle “llm_wizard.” His avatar: a laughing cartoon caricature sporting a slouchy sorcerer’s hat and brandishing a magic wand. </span></p>
<p><span style="font-weight: 400">It’s no surprise, then, that Alexiuk likens Nemotron to a magical library — its users fellow wizards in search of knowledge that can move mountains.</span></p>
<p><span style="font-weight: 400">“You’re a wizard in search of prepared spells, and Nemotron has a spell for everything,” he said. “Just choose the one you need.”</span></p>
<p><span style="font-weight: 400">In non-wizard terms?</span></p>
<p><span style="font-weight: 400">“There’s a category of model that’s going to be close to the kind of work you want to accomplish,” Alexiuk said, explaining that Nemotron supports that whole ecosystem of AI users: from individual developers using a model like Nemotron 3.5 Lightning for repetitive, high-frequency execution work to a company deploying Nemotron Ultra for long-running autonomous agents, deep research and enterprise tasks.</span></p>
<figure id="attachment_99666" aria-describedby="caption-attachment-99666" style="width: 1200px" class="wp-caption aligncenter"><img loading="lazy" decoding="async" class="wp-image-99666 size-large" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-1680x1120.jpg" alt="" width="1200" height="800" srcset="https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-1680x1120.jpg 1680w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-960x640.jpg 960w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-1280x853.jpg 1280w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-1536x1024.jpg 1536w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-scaled.jpg 2048w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-act-07-build-a-claw-BVB03323-1-630x420.jpg 630w" sizes="auto, (max-width: 1200px) 100vw, 1200px" /><figcaption id="caption-attachment-99666" class="wp-caption-text">NVIDIAN Chris Alexiuk (left) engages with developers during the Build-a-Claw event at GTC Berlin.</figcaption></figure>
<p><span style="font-weight: 400">“I think that openness helps more people understand AI and hopefully leads to more people doing really ingenious things with these tools at the limit,” Alexiuk said. “If a tool is amplifying skill, it’s amplifying human expression.”</span></p>
<h2><b>From Birding to Model-Building</b></h2>
<p><span style="font-weight: 400">Alexiuk first became fascinated with machine learning in a computational physics class at Trent University in Ontario, Canada.</span></p>
<p><span style="font-weight: 400">“After that, I learned about TensorFlow and that you could build image classifiers that ran on your GPU,” he recalled. As an initial one-off project, Alexiuk built a classifier that would alert him whenever his friend’s distinctive pet bird, a Yellow-Faced Gray Budgerigar, appeared in frame on his webcam during shared video game sessions.</span></p>
<p><span style="font-weight: 400">“Because we were playing video games, I wasn’t focused on my friend’s webcam, but I didn&#8217;t want to miss seeing the bird when it appeared,” Alexiuk said. “And then my whole life changed, because in that instance I realized it’s crazy what you could do with technology.”</span></p>
<p><span style="font-weight: 400">Since then, he’s been embedding himself in the open source AI community. </span></p>
<p><span style="font-weight: 400">“To imagine within the span of a few years going from freaking out because I could know my friend’s bird was in the camera frame to being able to make any website in a matter of minutes with a model that’s running on my laptop — I cannot wait to see what’s next,” Alexiuk said. “It’s never been more accessible to get into and learn about AI.”</span></p>
<p><span style="font-weight: 400">And if another LLM wizard arises to challenge him for the title of No. 1 Nemotron Fan?</span></p>
<p><span style="font-weight: 400">“It would be the greatest day of my life to be surpassed by an even bigger fan of Nemotron, who had heard about Nemotron through the work I was doing,” Alexiuk said. “That would be a capstone to my career that I can only dream of.”</span></p>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">Larger models, longer contexts and agentic applications are increasing GPU memory pressure while supply tightens and prices rise — a trend expected to continue through the near term.</span></p>
<p><span style="font-weight: 400;">NVIDIA works closely with memory partners to rapidly adopt the latest memory technologies. NVIDIA was first to adopt HBM3e and HBM4 technologies into an accelerated computing stack. </span></p>
<p><span style="font-weight: 400;">But the approach isn’t to simply pack more memory onto the GPU. It’s full-stack codesign. NVIDIA intentionally designs GPUs, CPUs, networking, storage and software together to get more useful work out of memory at every layer of the AI factory.</span></p>
<p><span style="font-weight: 400;">That matters because an AI factory runs on a memory and storage hierarchy. GPU high-bandwidth memory (HBM) is the fastest, most expensive and most contested tier — with model weights and KV cache competing for limited capacity. Below it sit CPU memory, local SSDs and shared storage, each trading speed for more capacity at a lower cost per bit. </span></p>
<p><span style="font-weight: 400;">How much useful work a byte does depends on how well the whole hierarchy is used: shrinking what must be stored, placing it on the right tier and bringing it back to the GPU before it’s needed. </span></p>
<p><span style="font-weight: 400;">Byte for byte, NVIDIA makes the most efficient use of memory at every layer — and the results show it. From NVIDIA Blackwell Ultra to the Vera Rubin platform, HBM capacity per GPU rose roughly 3%, while agentic throughput per dollar rose by up to 30x on SemiAnalysis AgentX.</span></p>
<h2><strong>Agentic Inference Is Putting More Pressure on HBM</strong></h2>
<p><span style="font-weight: 400;">Frontier models now have trillions of parameters — the values that hold what an AI model learned in training.</span></p>
<p><span style="font-weight: 400;">KV cache, which holds the context the model needs to understand each active request without reprocessing the same information, is also expanding. Agentic trajectories carry prior context across repeated model and tool calls, in some cases processing up to 3 million tokens, so each request’s working memory grows over time. </span></p>
<p><a href="https://blogs.nvidia.com/blog/what-is-retrieval-augmented-generation/"><span style="font-weight: 400;">Retrieval-augmented generation (RAG)</span></a><span style="font-weight: 400;"> adds relevant enterprise information to prompts, creating even more context to process and retain. </span></p>
<p><span style="font-weight: 400;">During inference, HBM primarily holds both model parameters and KV cache. The result: greater pressure on HBM. </span></p>
<p><img loading="lazy" decoding="async" class="alignnone size-full wp-image-99653" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-pressure.gif" alt="" width="1920" height="1080" /></p>
<h2><strong>Why AI Factories Need a Memory Hierarchy </strong></h2>
<p><span style="font-weight: 400;">Adding more HBM capacity per GPU is the obvious response to that pressure, but capacity delivers only what bandwidth can move. </span></p>
<p><span style="font-weight: 400;">Think of HBM as a warehouse and memory bandwidth as its loading docks. A larger warehouse holds more inventory, but the docks set how much can move in and out at a time. Once the docks are at capacity, moving more inventory takes longer and slows response times. If delays exceed the required service level, the added space can’t be used effectively, even as it adds cost and draws power. </span></p>
<p><span style="font-weight: 400;">That’s also why no operation keeps all its inventory in the closest, fastest space. What’s in motion stays near the line. What’s waiting moves to a larger, cheaper space nearby and returns before it’s needed. </span></p>
<p><span style="font-weight: 400;">An AI factory faces the same limit. </span></p>
<p><span style="font-weight: 400;">More HBM can hold more KV cache and support more concurrent users. Every added user shares the same compute and memory bandwidth. But when each user expects fast responses, eventually memory bandwidth is unable to supply data as fast as compute can use it: a limit engineers call the memory wall. </span></p>
<p><span style="font-weight: 400;">Past that point, extra HBM capacity can’t be put to work, yet it still adds costs and draws power. The data still needs a place to live, but not all of it needs the fastest, most expensive tier. This is why an AI factory manages data across a memory and storage hierarchy. </span></p>
<p><img loading="lazy" decoding="async" class="alignnone size-large wp-image-99674" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-1680x945.jpg" alt="" width="1200" height="675" srcset="https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-1680x945.jpg 1680w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-960x540.jpg 960w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-1280x720.jpg 1280w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-1536x864.jpg 1536w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-1290x725.jpg 1290w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-630x354.jpg 630w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-300x169.jpg 300w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1-400x225.jpg 400w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-hbm-throughput-plateau-1920x1080-1.jpg 1920w" sizes="auto, (max-width: 1200px) 100vw, 1200px" /></p>
<h2><strong>Maximizing the Value of Every Byte With Full-Stack Codesign</strong></h2>
<p><span style="font-weight: 400;">NVIDIA’s full-stack codesign makes every byte of HBM count by relieving pressure from model weights, KV cache and RAG data. It does this with techniques that each target a different source of inefficiency: </span></p>
<p><img loading="lazy" decoding="async" class="alignnone wp-image-99656 size-large" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-1680x945.jpg" alt="" width="1200" height="675" srcset="https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-1680x945.jpg 1680w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-960x540.jpg 960w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-1280x720.jpg 1280w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-1536x864.jpg 1536w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-1290x725.jpg 1290w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-630x354.jpg 630w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-300x169.jpg 300w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack-400x225.jpg 400w, https://blogs.nvidia.com/wp-content/uploads/2026/11/end-to-end-social-memory-blog-launch-5869521-memory-optimization-stack.jpg 1920w" sizes="auto, (max-width: 1200px) 100vw, 1200px" /></p>
<p><b>Shrink model weights and distribute them across the NVL72 domain.</b></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">The </span><a target="_blank" href="https://developer.nvidia.com/blog/3-ways-nvfp4-accelerates-ai-training-and-inference/"><span style="font-weight: 400;">NVFP4</span></a><span style="font-weight: 400;"> format reduces the space required for weights compared to FP8, the lowest precision possible on the NVIDIA Hopper platform. Recent models, including </span><a target="_blank" href="https://bfl.ai/blog/flux2-klein-towards-interactive-visual-intelligence"><span style="font-weight: 400;">FLUX.2 [klein]</span></a><span style="font-weight: 400;"> from </span><span style="font-weight: 400;">Black Forest Labs</span><span style="font-weight: 400;">, </span><a target="_blank" href="https://thinkingmachines.ai/news/introducing-inkling/"><span style="font-weight: 400;">Inkling</span></a><span style="font-weight: 400;"> from </span><span style="font-weight: 400;">Thinking Machines Lab, </span><a target="_blank" href="https://huggingface.co/reflection/Beam-1.0-501B-A23B-NVFP4"><span style="font-weight: 400;">Beam 1.0</span></a><span style="font-weight: 400;"> from Reflection</span><span style="font-weight: 400;">, </span><a target="_blank" href="https://developer.nvidia.com/blog/scale-agentic-coding-workflows-with-metas-muse-spark-open-on-nvidia-gb300-nvl72/"><span style="font-weight: 400;">Meta Muse Spark</span></a><span style="font-weight: 400;"> from </span><span style="font-weight: 400;">Meta</span><span style="font-weight: 400;">, </span><a target="_blank" href="https://huggingface.co/stepfun-ai/Step-5-Preview-NVFP4"><span style="font-weight: 400;">Step 5 Preview</span></a><span style="font-weight: 400;"> from StepFun</span><span style="font-weight: 400;"> and </span><a target="_blank" href="https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/"><span style="font-weight: 400;">NVIDIA Nemotron 3.5 Super VL</span></a><span style="font-weight: 400;"> have been released with NVFP4 checkpoints, demonstrating growing model-builder adoption of 4-bit precision for faster, more memory-efficient inference. </span></li>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">Within an NVL72 system, model weights can be </span><a href="https://blogs.nvidia.com/blog/mixture-of-experts-frontier-models/"><span style="font-weight: 400;">distributed across up to 72 GPUs</span></a><span style="font-weight: 400;">, so each GPU holds a smaller share of the model — leaving more HBM for KV cache and concurrent users. </span></li>
</ul>
<p><b>Shrink KV-cache and offload inactive context to lower-cost storage tiers.</b></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">Applying</span> <a target="_blank" href="https://developer.nvidia.com/blog/optimizing-inference-for-long-context-and-large-batch-sizes-with-nvfp4-kv-cache/"><span style="font-weight: 400;">NVFP4 to the KV cache</span></a><span style="font-weight: 400;"> reduces its footprint compared with FP8, so more context can stay resident in HBM.</span></li>
<li style="font-weight: 400;" aria-level="1"><a target="_blank" href="https://www.nvidia.com/en-us/data-center/vera-cpu/"><span style="font-weight: 400;">NVIDIA Vera CPU</span></a><span style="font-weight: 400;"> helps in two ways. Faster tool execution shortens the time KV cache sits inactive during tool calls, and its large LPDDR memory, connected to NVIDIA Rubin GPUs over NVIDIA NVLink-C2C interconnect, gives paused context a nearby place to wait and return quickly. </span></li>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">When context isn’t actively in use,</span> <a target="_blank" href="https://www.nvidia.com/en-us/ai/dynamo/"><span style="font-weight: 400;">NVIDIA Dynamo</span></a><span style="font-weight: 400;"> inference software moves it to</span> <a target="_blank" href="https://www.nvidia.com/en-us/data-center/ai-storage/cmx/"><span style="font-weight: 400;">NVIDIA CMX</span></a><span style="font-weight: 400;"> context memory storage — a tier built for capacity at far lower cost per bit than HBM — and returns it before reuse. Unlike local SSDs, CMX is shared across servers, and unlike enterprise storage, it skips the overhead of long-term data protection that short-lived context doesn’t need. NVIDIA CMX context memory storage partners include </span><span style="font-weight: 400;">Cloudian</span><span style="font-weight: 400;">,</span> <a target="_blank" href="https://www.ddn.com/press-releases/ddn-accelerates-inference-and-lowers-cost-per-token-while-expanding-multi-tenant-training-for-ai-factories/"><span style="font-weight: 400;">DDN</span></a><span style="font-weight: 400;">,</span> <a target="_blank" href="https://www.dell.com/en-us/dt/corporate/newsroom/announcements/detailpage.press-releases~usa~2025~11~dell-technologies-and-nvidia-advance-enterprise-ai-innovation.htm#/filter-on/Country:en-us"><span style="font-weight: 400;">Dell Technologies</span></a><span style="font-weight: 400;">, </span><a target="_blank" href="https://blog.purestorage.com/news-events/pure-kva-integrates-nvidia-dynamo-for-scalable-low-latency-llm-inference/"><span style="font-weight: 400;">Everpure</span></a><span style="font-weight: 400;"> (previously Pure Storage), </span><a target="_blank" href="https://www.hpe.com/us/en/newsroom/press-release/2026/03/hpe-unveils-next-generation-ai-factory-and-supercomputing-advancements-with-nvidia.html#:~:text=HPE%20AI%20Factory%20with%20Mission%20Control"><span style="font-weight: 400;">HPE</span></a><span style="font-weight: 400;">, </span><a target="_blank" href="https://community.ibm.com/community/user/blogs/vincent-hsu/2026/01/05/accelerating-nvidia-dynamo-with-ibm-storage-scale#:~:text=IBM%20is%20working%20with%20NVIDIA%20to%20combine,technologies%20to%20unlock%20scalable%2C%20high%2Dperformance%20LLM%20inference."><span style="font-weight: 400;">IBM</span></a><span style="font-weight: 400;">, </span><a target="_blank" href="https://www.netapp.com/newsroom/press-releases/news-rel-20250318-145499/"><span style="font-weight: 400;">NetApp</span></a><span style="font-weight: 400;">, </span><a target="_blank" href="https://www.vastdata.com/blog/how-nvidia-dynamo-vast-unlock-context-reuse-at-scale"><span style="font-weight: 400;">VAST</span></a><span style="font-weight: 400;"> and</span> <a target="_blank" href="https://www.weka.io/blog/ai-ml/weka-accelerates-ai-inference-with-nvidia-dynamo-and-nvidia-nixl/"><span style="font-weight: 400;">WEKA</span></a><span style="font-weight: 400;">. </span></li>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">Dynamo’s KV Cache Reuse ties the tiers together, managing KV cache as one system-wide resource across GPU memory, CPU memory and storage, so context computed once can be reused across the system. </span></li>
</ul>
<p><b>Compact RAG embeddings and keeping the index outside HBM.</b></p>
<ul>
<li style="font-weight: 400;" aria-level="1"><span style="font-weight: 400;">RAG turns enterprise documents into embeddings — numerical representations that let a system search by meaning rather than keyword — organized into a searchable index. NVIDIA Nemotron Retriever models produce smaller embeddings with higher retrieval accuracy, while the NVIDIA cuVS library enables that index to be built and served across CPU and storage. The knowledge base never occupies HBM, and only the passages the model needs enter context. </span></li>
</ul>
<p><span style="font-weight: 400;">The result is less HBM used for model weights, less HBM tied up by idle context and more of it available to serve concurrent users. </span></p>
<h2><strong>More Useful Output per Dollar With Each Generation</strong></h2>
<p><span style="font-weight: 400;">Across successive NVIDIA platform generations, tokens per second per dollar has risen far faster than HBM capacity. </span></p>
<p><span style="font-weight: 400;">On the SemiAnalysis AgentX DeepSeek V4 Pro workload, NVIDIA GB300 NVL72 delivers up to 10x higher throughput per dollar than NVIDIA H200 platform at 100 tokens per second per user, with HBM capacity per GPU roughly doubling. At 125 tokens per second per user, Vera Rubin NVL72 delivers up to 30x higher throughput per dollar than GB300 NVL72, with HBM capacity per GPU up about 3%. </span></p>
<p><img loading="lazy" decoding="async" class="alignnone size-large wp-image-99657" src="https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-1680x1120.jpg" alt="" width="1200" height="800" srcset="https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-1680x1120.jpg 1680w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-960x640.jpg 960w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-1280x854.jpg 1280w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-1536x1024.jpg 1536w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-scaled.jpg 2048w, https://blogs.nvidia.com/wp-content/uploads/2026/11/26gtc-eu-keynote-LD2_0199-1-630x420.jpg 630w" sizes="auto, (max-width: 1200px) 100vw, 1200px" /></p>
<p><span style="font-weight: 400;">For AI factory operators, the metric that matters is how many useful tokens the factory can deliver within its power budget while meeting user response-time needs. More tokens per second per watt means more work and revenue from the same power, and a lower cost for every token. NVIDIA’s full-stack codesign lowers token costs by increasing the useful work every byte of memory delivers. </span></p>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">Demand for advanced chips is rising. The processes to build them are getting more complex. And the margin for error is shrinking.</span></p>
<p><span style="font-weight: 400;">For engineers, understanding how a process change will behave, how a material will interact with a new step, how a defect maps back to a root cause are critical, challenging steps in semiconductor manufacturing — and these analyses can take days. Physical experiments on a fab line are slow and expensive. A wrong call on yield or process quality has real consequences.</span></p>
<p><span style="font-weight: 400;">AI is transforming semiconductor manufacturing, impacting what engineers can do — and how fast. </span></p>
<p><span style="font-weight: 400;">Accelerated computing shortens simulation time, allowing engineers to evaluate more alternatives before committing to physical trials. </span></p>
<p><span style="font-weight: 400;">Physics-based AI helps engineers predict process behavior without running a full simulation every time. </span></p>
<p><span style="font-weight: 400;">AI agents handle sequences of engineering tasks that once consumed hours. </span></p>
<p><span style="font-weight: 400;">And </span><a target="_blank" href="https://www.nvidia.com/en-us/glossary/digital-twin/"><span style="font-weight: 400;">digital twins</span></a><span style="font-weight: 400;"> let teams test changes in a virtual environment before committing to physical trials.</span></p>
<p><span style="font-weight: 400;">Together, these capabilities describe an AI-defined fab: a </span><a target="_blank" href="https://www.nvidia.com/en-us/industries/semiconductor/"><span style="font-weight: 400;">semiconductor</span></a><span style="font-weight: 400;"> manufacturing factory where AI helps engineers optimize processes, catch problems earlier and make better decisions across the full manufacturing chip lifecycle. Engineers direct the work and make decisions based on their expertise while spending less time waiting for answers.</span></p>
<p><iframe loading="lazy" title="How NVIDIA AI Is Transforming Chip Design and Manufacturing" width="1200" height="675" src="https://www.youtube.com/embed/rBN0PDfJWIc?feature=oembed" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen></iframe></p>
<h2><strong>Shorter Simulation Cycles Change What Engineers Can Explore</strong></h2>
<p><span style="font-weight: 400;">Accelerated computing doesn’t just speed up individual calculations — it changes how many alternatives engineers can test before committing. </span></p>
<p><span style="font-weight: 400;">Multiphysics simulations model interactions among physical effects, such as heat transfer, electrical behavior and mechanical stress. </span></p>
<p><span style="font-weight: 400;">Using the </span><a target="_blank" href="https://developer.nvidia.com/cudss"><span style="font-weight: 400;">NVIDIA cuDSS</span></a><span style="font-weight: 400;"> library, multiphysics simulation software provider </span><a target="_blank" href="https://www.comsol.com/blogs/accelerating-semiconductor-manufacturing-simulation-with-nvidia-cudss"><span style="font-weight: 400;">COMSOL</span></a><span style="font-weight: 400;"> is accelerating such simulations for semiconductor manufacturing by up to 10x. This helps engineers optimize equipment and processes, compare alternatives and decide which changes to test physically.</span></p>
<p><span style="font-weight: 400;">Applied Materials and NVIDIA are collaborating to accelerate atomic-scale materials discovery and process development. By integrating NVIDIA cuDSS, Applied’s Ginestra simulation platform runs up to 10x faster than CPU-only approaches. And with NVIDIA PhysicsNeMo, Applied’s ACE+ multiphysics platform delivers topography simulations up to 35x faster.</span></p>
<p><span style="font-weight: 400;">In some cases, acceleration doesn’t just shorten the calculation — it enables it altogether. Computational lithography — which defines how circuit patterns are printed onto silicon — involves calculations too intensive to complete on CPU at production scale. Siemens is integrating</span> <a target="_blank" href="https://developer.nvidia.com/culitho"><span style="font-weight: 400;">NVIDIA cuLitho</span></a><span style="font-weight: 400;"> into its Calibre lithography software, delivering up to 17x acceleration on key simulation workloads. That expands what engineers can verify before a wafer goes to print.</span></p>
<p><span style="font-weight: 400;">As such, faster calculations can help researchers explore material behavior and reaction pathways that influence next-generation semiconductor processes.</span></p>
<h2><strong>Predicting Process Behavior Without Running Every Simulation</strong></h2>
<p><span style="font-weight: 400;">In addition to accelerating simulations, AI trained on physics can predict how materials and processes will behave — without running a full simulation each time.</span></p>
<p><span style="font-weight: 400;">The payoff is most visible in complex calculations that are expensive even on accelerated hardware.</span></p>
<p><span style="font-weight: 400;">Plasma — the electrically charged gas used in semiconductor etch processes — is one example. Modeling plasma behavior requires solving equations that capture how electrical, chemical and thermal processes interact, making repeated simulation costly. </span><a target="_blank" href="https://developer.nvidia.com/physicsnemo"><span style="font-weight: 400;">NVIDIA PhysicsNeMo</span></a><span style="font-weight: 400;"> can assist in reducing plasma-prediction simulation time from days to as little as milliseconds. </span></p>
<p><span style="font-weight: 400;">Lam Research intends to integrate NanoVDB into its advanced semiconductor process modeling platform SEMulator3D, part of the company’s Semiverse Solutions family of virtual products. The addition of NanoVDB is expected to accelerate select wafer-etch modeling by up to 30x.</span><span style="font-weight: 400;"><br />

<h2><strong>Agents Handle the Steps Between Decisions</strong></h2>
<p><span style="font-weight: 400;">Engineers turn analyses into decisions — revising a design, investigating a test failure, adjusting a production process and more. </span></p>
<p><span style="font-weight: 400;">AI agents can help carry out the steps between those decisions.</span></p>
<p><span style="font-weight: 400;">Evaluating which AI model to apply to a given task is one example: a sequential, manual process that can consume hours on the test floor. </span></p>

<h2><strong>Testing Factory Changes Before They Reach the Line</strong></h2>
<p><span style="font-weight: 400;">Digital twins let teams simulate equipment configurations, layouts and process changes in a virtual environment before committing to physical trials. This reduces experimentation costs, especially as fabs become more complex and the stakes of a wrong change get higher.</span></p>

										<content:encoded><![CDATA[<div id="bsf_rt_marker"></div><p><span style="font-weight: 400;">While science fiction lore tells us that humans will meet extraterrestrial life in the form of little green men, the detail that should raise hairs this Halloween is this: the search for extraterrestrial intelligence took a major leap forward with AI, and it increasingly focuses on AI agents built by humans listening for AI agents built by aliens.</span></p>
<p><span style="font-weight: 400;">Some scientists have suggested that extraterrestrial civilizations, if they exist, could be billions of years older than humanity. Such civilizations might have developed technologies far beyond humanity’s, including forms of AI.</span></p>
<p><span style="font-weight: 400;">Breakthrough Listen and the SETI Institute are bringing agentic AI into the daily search for extraterrestrial intelligence. At the</span> <a target="_blank" href="https://www.seti.org/seti-allen-telescope-array-ata"><span style="font-weight: 400;">Allen Telescope Array</span></a><span style="font-weight: 400;"> in Northern California, agents can now steer the instrument, enhance and correct incoming data, and apply AI models to the incoming stream — all from a single natural language request. The </span><a target="_blank" href="https://www.nvidia.com/en-us/edge-computing/holoscan/"><span style="font-weight: 400;">NVIDIA Holoscan</span></a><span style="font-weight: 400;"> platform processes the massive streams of sensor data, giving agents live data to act on.</span></p>
<p><span style="font-weight: 400;">The result is a faster, more adaptable search for potential signals from extraterrestrial life and technologies.</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;"><br />
</span><span style="font-weight: 400;">“As our new agentic observatories reach out into the universe, what they find may have much more in common with themselves than with the humans who created them,” said Andrew Siemion, Bernard M. Oliver chair for SETI at the SETI Institute and principal investigator of Breakthrough Listen. “But this isn&#8217;t something to fear. Rather, it’s a breakthrough in translation.”</span></p>
<h2><strong>Terabits a Second, Processed in Flight</strong></h2>
<p><span style="font-weight: 400;">Radio telescopes generate enormous volumes of data, creating a challenge for scientists who need to identify potentially interesting signals as observations unfold.</span></p>
<p><span style="font-weight: 400;">At the Allen Telescope Array, </span><a target="_blank" href="https://developer.nvidia.com/daqiri"><span style="font-weight: 400;">DAQIRI</span></a><span style="font-weight: 400;">, a Holoscan platform library, enables the telescope to pull terabits per second of sensor data straight into GPU memory so observations are processed in flight rather than filling hard drives. </span><a target="_blank" href="https://cyberether.org"><span style="font-weight: 400;">CyberEther</span></a><span style="font-weight: 400;">, a signal-processing framework developed at the SETI Institute, does the math using NVIDIA CUDA-X libraries including </span><a target="_blank" href="https://developer.nvidia.com/cufft"><span style="font-weight: 400;">cuFFT</span></a><span style="font-weight: 400;"> and </span><a target="_blank" href="https://developer.nvidia.com/cublas"><span style="font-weight: 400;">cuBLAS</span></a><span style="font-weight: 400;">.</span></p>
<p><a target="_blank" href="https://stelline.space"><span style="font-weight: 400;">Nexus</span></a><span style="font-weight: 400;">, a web-based observatory orchestrator, acts as the agent harness. It gives agents a single source of truth for instrument state, compute resources and pipelines and lets researchers monitor packet loss, read live spectrograms and rewrite signal-processing blocks — all by prompting in natural language. The system can handle 2.4 terabits per second on NVIDIA RTX PRO 6000 Blackwell GPUs, with inference running on premises, next to the instrument.</span></p>
<p><span style="font-weight: 400;">Put together, the system enables an agent to steer a telescope’s antennae, calibrate and focus the instrument for a clean signal, catch and fix data errors and plot the result. Agents compress what would take humans weeks or years into hours.</span></p>
<h2><strong>Science Fact, Not Fiction</strong></h2>
<p><span style="font-weight: 400;">The pipeline has already proven itself, achieving the first real-time AI detection of a pulsar — a rapidly spinning stellar remnant that pulses like a cosmic lighthouse — in the Crab Nebula. </span></p>
<p><span style="font-weight: 400;">Next, the team is evaluating open models including </span><a target="_blank" href="https://www.nvidia.com/en-us/ai-data-science/foundation-models/nemotron/"><span style="font-weight: 400;">NVIDIA Nemotron</span></a><span style="font-weight: 400;"> for cases where data locality and turnaround matter most and for observatories that may someday run offline on the far side of the moon.</span></p>
